<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker supervisor -> DB owner process | Process topology decides who may open the DuckDB file read-write. |
| Healthcheck -> live service | Health probes must not corrupt or lock the live database. |
| Refresh scheduler -> repository | Background writer runs inside the DB owner boundary. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-08-04-02 | Tampering | `deploy/healthcheck.py` | mitigate | Healthcheck validates via HTTP/owner readiness instead of live read-write DB open. |
| T-08-04-03 | Tampering | refresh runtime | mitigate | Existing lease/backoff/checkpoint tests preserved under owner-process scheduling. |
| T-08-04-04 | Information Disclosure | Docker/runtime config | mitigate | No new public host port or token/log exposure; DB path only is reported. |
| T-08-04-SC | Tampering | DuckDB dependency | mitigate | Depends on 08-01 package gate and 08-03 repository cutover. |
