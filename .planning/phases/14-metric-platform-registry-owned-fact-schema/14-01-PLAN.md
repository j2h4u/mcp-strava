<objective>
Make the fact-column registry capable of describing the current DuckDB
`activity_metric_facts` schema without changing runtime schema creation yet.

This is the TDD/setup step for Phase 14. Add SQL schema metadata to
`FactColumnDefinition`, populate it for all materialized fact columns, and add
small helper functions that can render the `activity_metric_facts` column
definitions from the registry. Keep `schema.py` untouched in this plan so the
first diff is mechanically verifiable and rollback-safe.

The registry metadata must be strong enough to reproduce the existing
hand-written `activity_metric_facts` DDL:

- `sql_type`: exact DuckDB type token (`BIGINT`, `DOUBLE`, `VARCHAR`, `DATE`)
- `nullable`: false for current `NOT NULL` columns, true for nullable columns
- `default_sql`: SQL default expression where the current DDL has one

Do not start the later metric-platform slices. No source grammar, no materializer
dispatch changes, no payload-generation changes, and no rematerialize command.
</objective>
