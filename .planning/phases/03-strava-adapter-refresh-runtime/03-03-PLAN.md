- D-19: Implemented by (a) `CREATE UNIQUE INDEX idx_refresh_requests_dedupe ON refresh_requests(reason, requested_for_day) WHERE consumed_at IS NULL` in migration v2; (b) `mark_refresh_requests_consumed(consumed_at)` (no ids parameter) marking the entire pending set per pass.
- REFRESH-02: Implemented by `pending_refresh_requests` and `mark_refresh_requests_consumed` methods so the refresh-runtime can consume signals without coupling to MCP/read modules.
- REFRESH-03: Implemented by `acquire_refresh_lease` and `release_refresh_lease` using atomic UPDATEs gated on lease expiry; second concurrent caller observes `False`.
- STRAVA-03: Implemented by `set_checkpoint(stage, cursor)` and `record_refresh_*` methods so resume after interruption preserves prior work.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration tooling -> mirror DB | DDL must extend, not alter existing tables; backup/preflight remain mandatory. |
| Repository -> callers | Callers (refresh-runtime, read-runtime) must use typed methods; raw SQL stays inside the adapter. |
| Reason-code writes -> SQLite | Only product-safe codes may land in `last_error_code`. |

| T-03-07 | Information Disclosure | `record_refresh_failure` | mitigate | Whitelist of reason codes prevents stack traces or token values from leaking into `last_error_code`. |
| T-03-SC | Tampering | package installs | accept | No package-manager installs are planned for this plan. |
