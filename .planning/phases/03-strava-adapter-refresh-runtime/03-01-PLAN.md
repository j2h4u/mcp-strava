<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem -> Token Provider | Token file may be partially written, world-readable, or held by another process. |
| Adapter -> Strava API | Network may fail, return 401/429, or be tampered with at the OS level. |
| Adapter -> Logs | Token values must never escape into stdout, stderr, or exception messages. |
| Adapter -> Rate-limit policy | Missing or malformed headers must not produce false `proceed` decisions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `token_provider.py` | mitigate | Exclusive `fcntl.flock` + tempfile + `os.fsync` + `os.replace` + `0o600` chmod; concurrency test asserts only one upstream refresh. |
| T-03-02 | Information Disclosure | `transport.py` / `token_provider.py` / `token_refresh.py` | mitigate | Adapter never logs or raises token/refresh_token/client_secret values; tests capture stderr/stdout and assert absence across both 401-refresh and OAuth-failure code paths. |
| T-03-03 | Denial of Service (self) | `rate_limit.py` / `transport.py` | mitigate | Dual-window dual-scope policy enforces the stricter remaining budget; typed `StravaUnavailable('rate_limited')` keeps callers honest. |
| T-03-10 | Denial of Service (self) | `token_refresh.py` / `transport.py` | mitigate | D-18: separate retry budgets for OAuth refresh (3 attempts, `[2,8,30]` backoff) vs data fetch (3 attempts, `[1,5,30]` backoff) so a flaky OAuth endpoint cannot exhaust the data-fetch retry budget (and vice versa). Tests assert independent counters. |
| T-03-SC | Tampering | package installs | accept | No package-manager installs are planned for this plan. |
</threat_model>
