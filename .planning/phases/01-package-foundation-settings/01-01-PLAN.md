<threat_model>
Trust boundaries:
- Local source tree and package metadata are trusted developer-controlled files.
- `.env`, `.planning/config.json`, and `data/strava.db` are local runtime state and must not be committed or modified by packaging work.
- Strava API/network calls are outside this phase.

Threat register:
- T01 | Tampering | `data/strava.db` | Mitigated by excluding `data/` from `files_modified`, avoiding migration/sync commands, and verifying the DB file still exists after the move.
- T02 | Information disclosure | `.env` and `.planning/config.json` | Mitigated by not reading secret values into generated files and not staging ignored config files.
- T03 | Spoofing/import confusion | Python import path | Mitigated by using `src/mcp_strava` imports and removing `strava_lib.*` imports from package source.
- T04 | Boundary regression | CLI executable contract | Mitigated by requiring `python -m mcp_strava` and forbidding `[project.scripts]` for `mcp-strava` in this phase.
- T05 | Verification false negative | Non-pytest commands | Mitigated by explicitly running source-tree checks with `PYTHONPATH=src` until the editable-install smoke proves the package is importable without pytest.
</threat_model>
