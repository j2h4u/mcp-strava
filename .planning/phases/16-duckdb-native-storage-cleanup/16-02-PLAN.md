<objective>
Drop `activities.date VARCHAR` and make the kudos store native DuckDB.

This is the highest-impact change in Phase 16. The `date` column duplicates the
native `activity_day DATE` column — same local day, written from the same source
string. The `window_days` branch in kudos_store.py uses `date('now', ?)`, a
SQLite-only function that raises ParserException on DuckDB. That branch is
currently dead (both callers pass window_days=None) — Plan 16-01 added the
regression test that will flip from xfail to passing after this plan.

Two coupled changes in one commit (same column drives both):
1. Remove `date VARCHAR` from schema DDL + `upsert_activity_summary`.
2. Rewrite kudos window_days branch to `CURRENT_DATE - (? * INTERVAL '1 day')`.
3. Update every SQL reader of `a.date` → `a.activity_day`.
4. Rename `RepositoryActivityRow.date` → `activity_day` (still `str`; callers
   that read `.date` must be updated).

No migration. The DB is recreated from source on next resync.

Purpose: Remove SQLite-era dead weight; activate a latent DuckDB bug before it
bites; preserve byte-for-byte identical external behavior (activity_date alias
stays "YYYY-MM-DD" because str(datetime.date) yields the same format).
Output: Cleaner schema, working kudos window filter, passing Wave 0 test.
</objective>
