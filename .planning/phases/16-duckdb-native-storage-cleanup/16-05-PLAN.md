<objective>
Convert `missing_reasons_json VARCHAR` to `VARCHAR[]` in all four fact tables
and eliminate the Python double-json.loads decode.

This is the highest-complexity change in Phase 16 — it touches the schema DDL,
the registry allowlists, two write paths, three aggregate SQL expressions, and
the decode path. All changes flow in one direction: replace JSON-string
serialization with native DuckDB array semantics end-to-end.

The DB is recreated from source on next resync. No migration, no compat shim.
After this plan, `missing_reasons_json` stores native `list[str]`, aggregates
via `list_distinct(list_flatten(list(col)))` in SQL, and decodes as a plain
Python list — no JSON involved.

Purpose: Replace ad-hoc JSON-string array encoding with native VARCHAR[] array.
Output: Four tables with VARCHAR[] column; clean write helpers; flat-list decode.
</objective>
