## Full Column Mapping (all 14 — resolves the 13-vs-14 ambiguity)

The executor MUST populate every row below. The earlier "13 columns" wording undercounted by excluding
`cardiac_drift_significant` (which defaults to `0` and is handled specially, not via a direct `.field`
read). There are 14 hardcoded defaults; all 14 are wired here.

| # | Column | Default now | Source (pure fn → field) |
|---|--------|-------------|--------------------------|
| 1 | `hr_recovery_pause_count` | `0` | `calc_hr_recovery(rows).pauses_found if hr else 0` |
| 2 | `hr_recovery_total_rest_sec` | `0` | `hr.total_rest_sec if hr else 0` |
| 3 | `hr_recovery_median_rate` | `None` | `hr.median_rate if hr else None` |
| 4 | `hr_recovery_best_rate` | `None` | `hr.best_rate if hr else None` |

| 8 | `vertical_speed_total_ascent_m` | `None` | `vspeed.total_ascent_m if vspeed else None` |
| 9 | `vertical_speed_duration_hours` | `None` | `vspeed.duration_hours if vspeed else None` |

**Note on `cardiac_drift_significant` semantics (carried over, unchanged):** `1 if (drift and
drift.is_significant) else 0` collapses "insufficient data" and "computed-but-not-significant" into the
same `0`. This is pre-existing design, not introduced here — flagged as a conscious carry-over.

## metric_version decision (explicit)

**Decision: do NOT bump `metric_version` in this phase.** Rationale: the column set, registry contract, and
formula identities are unchanged — only the materializer stops writing defaults and starts writing the
already-defined computed values. No consumer cache keys off `metric_version` for these columns, and the
live refresh is an explicit operator-run re-materialize (decision 7), not a version-triggered invalidation.
Keeping `metric_version` fixed avoids spuriously invalidating unrelated cached facts. If a future change
alters a formula or column set, THAT change bumps `metric_version`. The post-deploy sanity query in the
decision-7 live-ops note is the verification that the re-materialize did what's expected.
