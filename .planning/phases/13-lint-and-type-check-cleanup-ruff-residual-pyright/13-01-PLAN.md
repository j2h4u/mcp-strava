<objective>
Clear the dominant pyright error clusters by widening two type boundaries at their source.

D-01: Introduce `Row = dict[str, Any]` module-level alias in repository.py and change `_fetchone` → `dict[str, Any] | None`, `_fetchall` → `list[dict[str, Any]]`, `_scalar` → `Any | None`. These methods synthesize dicts from raw DuckDB tuples and result descriptions — `Any` is the honest type. This single change clears the ~326-error cluster (reportArgumentType, reportAttributeAccessIssue, reportIndexIssue, and most reportOptionalSubscript/reportOptionalMemberAccess).

D-03: Annotate `dc_to_dict` in types.py with `-> Any`. The missing return annotation causes pyright to infer a deeply-nested recursive union, which cascades into reportReturnType + reportCallIssue (__setitem__/__getitem__) in aggregate_services.py, product_facts.py, and cli.py. `-> Any` collapses all downstream errors at the converter.

Purpose: Eliminate the two largest error sources before the residual sweep in Plan 02. These are independent files — D-01 and D-03 can be applied in any order in the same task pass.

Output: repository.py with Row alias + widened fetch signatures; types.py with annotated dc_to_dict.
</objective>
