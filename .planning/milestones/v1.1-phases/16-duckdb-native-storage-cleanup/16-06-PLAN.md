<objective>
Low-risk SQL cleanup: remove no-op CASTs from views and eliminate the
per-row Python json.loads loop in stream channel coverage.

Task 5a (schema_views.py): Every `CAST(x AS DATE)` where `x` is already a DATE
column is a DuckDB no-op — it cannot change behavior. Removing them eliminates
misleading implicit-conversion noise and makes the views cleaner.

Task 5b (stream_coverage_queries.py): The current channel-presence check fetches
ALL values_json strings for an activity and runs json.loads on each in Python.
Replacing it with a single SQL `json_extract_string(values_json, '$.' || ?) IS NOT NULL`
predicate moves the work into DuckDB, eliminates the Python deserialization, and
reads at most 1 row instead of N.

This is the final plan in Phase 16. After this plan, the full suite gate runs
and the phase is ready for verification.

Purpose: Remove SQLite-era noise (CAST no-ops) and fix an N+1 Python deserialize
anti-pattern.
Output: Two cleaner files; no behavior change.
</objective>

  <action>
  The current implementation (lines ~77-90) fetches all `values_json` strings
  for an activity and checks `channel in json.loads(...)` in Python for each row.
  This is an N-row Python deserialization for what is logically a single
  existence check.

  **Replace the entire `value_rows` fetch + Python `any(...)` loop block with
  a single `_fetchone` SQL existence predicate:**

  Remove:
      value_rows = repo._fetchall(
          """
          SELECT values_json
          FROM streams
          WHERE activity_id=?
            AND values_json IS NOT NULL
          """,
          [activity_id],
      )
      if not any(
          channel in (json.loads(str(item["values_json"])) if item["values_json"] else {})
          for item in value_rows
      ):
          missing_channels.append(channel)

  Replace with:
      exists_row = repo._fetchone(
          """
          SELECT 1 FROM streams
          WHERE activity_id = ?
            AND json_extract_string(values_json, '$.' || ?) IS NOT NULL
          LIMIT 1
          """,
          [activity_id, channel],
      )
      if exists_row is None:
          missing_channels.append(channel)

  Notes on the SQL:
  - `values_json` is a `VARCHAR` column — `json_extract_string` operates on
    VARCHAR in DuckDB.
  - `'$.' || ?` concatenates the JSON root path with the channel key via a
    bound parameter. The channel key comes from a validated closed set (Strava
    stream keys) — not user input — but the bound-param form is still safer and
    matches the project pattern.
  - `IS NOT NULL` means the key exists AND has a non-null value. This is
    equivalent to `channel in json.loads(str(values_json))` (a present key with
    a null value would be excluded by both forms).
  - `LIMIT 1` — only need to find one matching stream row.

  After the replacement, check whether `import json` in
  `stream_coverage_queries.py` has any remaining uses. If not, remove it.

  Also check whether the removed `value_rows` variable was used anywhere else
  in the same scope. It should not be — confirm before deleting.
