<gps_migration_contract>
- Migration version is `4`. `MIGRATIONS[4]` or equivalent runs after the Phase 6 v3 stream-channel migration and is idempotent when `PRAGMA user_version` is already 4.
- Required inventory is versioned: v3 requires `streams.latlng`; v4 requires `streams.lat`, `streams.lng`, and `streams.values_json` but excludes `streams.latlng`.
- GPS precedence is deterministic: non-null scalar `lat`/`lng` values win over `latlng` JSON. Fill scalar coordinates from `latlng` only when doing so does not overwrite a non-null scalar. If scalar values disagree with `latlng` beyond a small numeric tolerance, preserve the scalar values and count the row in a `gps_scalar_latlng_conflict_count` post-check warning.
- Malformed `latlng` JSON never aborts the migration. Preserve the row, leave missing scalar coordinates null, and count it in `gps_malformed_latlng_count`.
- `latlng` removal uses an explicit SQLite table rebuild inside one transaction: create `streams_new` with the final v4 columns and the same primary key, copy rows with converted GPS values, drop old `streams`, rename `streams_new`, and recreate `idx_streams_act` plus any Phase 6 stream indexes. Do not rely on `ALTER TABLE DROP COLUMN`.
</gps_migration_contract>
