# BLOCKING CONSTRAINTS — Read Before Anything Else

- [ ] **CONSTRAINT: Admin CLI commands cannot open the DB while the owner runs.** Post-Phase-8 regression: DuckDB holds an exclusive file lock on `/runtime/data/strava.duckdb`. Verified empirically — `docker compose exec mcp-strava python ...` from a second process inside the same container fails with `Could not set lock on file ... Conflicting lock is held in PID 1`. Pre-Phase-8 SQLite WAL allowed this; DuckDB does not. Do not assume any `python -m mcp_strava admin <cmd>` works against a running container — none of them have actually worked since 2026-05-25.
- [ ] **CONSTRAINT: This is a single-user install-and-forget service.** Apply this constraint *before* designing any CLI/admin/operator workflow. If a proposal assumes there is an "operator" who knows when to run maintenance commands, the proposal is wrong. Real annual admin command invocations: ~5. The user has been calling out reflexive "enterprise operator" framings all session, every single time correctly. The dead Russian coaching strings, the cargo doc-content tests, the two-similar-backfill-commands UX, the IPC reflex on admin compact — all the same anti-pattern.

**Do not proceed until both boxes are checked.**

|---------|-------------|----------|----------------------|

<decisions_made>

- **Don't build IPC / live admin transport.** Kaizen verdict, agrees with user pushback all day. Building admin HTTP/socket + pause-resume protocol + atomic-swap-with-in-flight-requests for 5 events per year is over-engineering. Ship Option D (stop+start workflow, invisible via wrapper).
- **Compact runs against a stopped owner.** Strictly simpler — no pause/resume, no MCP request draining, no atomic-swap-with-open-file edge case.
- **Merge backfill + backfill-streams; delete mirror-refresh.** "Missing rows" vs "missing channels of existing rows" is real but irrelevant to a single user. mirror-refresh is a footgun.
- **Internal naming: `_fetch_missing_activities` + `_fetch_missing_stream_channels` (not `enrich`)** as the two phases inside `run_catchup`. Plain English; no data-warehouse jargon.
- **DB bloat is one-time aftermath of 2026-05-25 migration, not ongoing.** Day-in-day-out bloat is negligible (verified via `read_model_refresh_runs` timeline). No periodic compaction; compaction belongs at the tail of known bulk operations only.
- **weekly_digest is not slower because of inefficiency** — bucket=week is real work. Leave it. Future structural lever (pre-materialize weekly buckets) is filed, not urgent.
- **HR-zone refactor approach** (carried from prior session): zones computed on the fly from running HRmax-to-date + config HR_REST; model id (`karvonen_hrr`) persisted per-activity. No hidden defaults — fail-fast if `MCP_STRAVA_HR_REST` unset. Now enforced at owner startup, not lazily.

## Critical Anti-Patterns (do NOT repeat these)

- **Proposing periodic systemd timers, in-process maintenance threads, IPC admin transports, or any "operator workflow"** for a single self-hosted user. Apply the "~5 events per year" sanity check before any such proposal.
- **Inventing command names** that don't exist (`cutover-script`, `admin rematerialize-all`, etc.). Grep the actual `ADMIN_COMMANDS` dict before proposing hooks.
- **Quoting constants in documentation** (`500 ms`, `Phase 9 target`, named env-var values). Reference the command/recipe/code that carries the value; the documentation is not the source of truth.
- **Reflexively defending "doc-content tests"** as registry-sync contracts. They assert substring presence, which is not sync. If a real contract is needed, generate the doc from code.
