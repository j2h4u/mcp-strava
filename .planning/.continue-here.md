## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Per-row read/write in a loop on DuckDB | DuckDB has high per-STATEMENT latency (~2-4ms; analytical/columnar, not OLTP). Hundreds–thousands of single-key INSERT/SELECT statements in a Python loop is the dominant cost. Fixed: stream INSERTs, materializer fact UPSERTs, per-day daily READS. Remaining: `_activity_fact`'s 10 per-activity reads. | advisory | Batch via multi-row VALUES / `GROUP BY id` / `IN`-list; push set computation into SQL window functions. Profile with `pytest --durations` + cProfile by `tottime` (cProfile INFLATES import machinery ~8x — trust `_duckdb.execute` C-time + statement COUNTS). |
| Silently revising a VALIDATED decision | Phase 3 pushes metric math into SQL, which revises the Phase-10 "pure storage-free domain, unit-testable without a DB" contract (AST import-boundary guard enforces it). | advisory | The expert panel MUST resolve this tension explicitly and log the decision; do not let it slip through as an implementation detail. |
| Acting on agent/panel findings as facts | The N+1 audit findings are leads. | advisory | Re-grep `file:line` + read the method before refactoring; re-derive severity. |
