## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Per-row write/read in a loop on DuckDB | DuckDB has high per-STATEMENT latency (~2-4ms; analytical/columnar, not OLTP). Code that emits hundreds–thousands of single-row INSERT/SELECT statements is inherently slow. Found in stream inserts (fixed) and the materializer (writes fixed Phase 1; ~2000 per-day reads remain). | advisory | Batch writes via multi-row `INSERT … VALUES(…),(…)` capped ~250 rows/stmt; batch reads via range/`IN` SELECTs. Profile with `pytest --durations` + cProfile by `tottime` — but cProfile INFLATES import machinery ~8x, so trust `_duckdb.execute` C-time and statement COUNTS, not the import-machinery rows. |
| Local checks narrower than CI | `just lint`/`fmt-check` covered only `src tests` while CI lints `.` (whole repo incl. deploy/) → two red-CI pushes this session. | advisory | Run `just preflight` before pushing; keep Justfile SCOPE aligned to `.github/workflows/ci.yml`, not just the commands. |
