<objective>
Make the regular hourly SUMMARIES stage incremental: pass `&after=<epoch>` to Strava's
`/athlete/activities` so a normal run fetches only new activities (~1 API call), while a
weekly (configurable) full walk remains the safety net for edits/anomalies.

Purpose: Eliminate the O(history) API call on every hourly refresh; stay within Strava
rate limits on larger accounts.

Output:
- `sync_summaries` accepts `after_epoch: int | None`
- `run_once` selects FULL vs. INCREMENTAL based on `last_full_summary_sync_at` marker
- `last_full_summary_sync_at` nullable column on `refresh_state` added via ALTER TABLE (live DB safe)
- `full_resync_interval_seconds` setting (default 604800)
- Unit test suite covering (a) URL construction, (b) full/incremental gate logic,
  (c) cold-start, (d) additive-column compatibility
</objective>
