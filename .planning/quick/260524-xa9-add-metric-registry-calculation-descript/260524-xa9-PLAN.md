# Quick Task 260524-xa9 - Add Metric Registry Calculation Descriptions

## Goal

Make the metric registry self-describing enough that agents can understand how every exposed metric is calculated without reading implementation code.

## Tasks

| Task | Files | Action | Verify |
|------|-------|--------|--------|
| 1 | `src/mcp_strava/types.py`, `src/mcp_strava/application/metric_registry.py` | Add a required `calculation` field to `MetricDefinition` and populate it for every metric. | Registry import succeeds; every metric has non-empty calculation metadata. |
| 2 | `src/mcp_strava/application/metric_registry.py`, `docs/metrics.md` | Include calculation metadata in catalog payloads and public metric docs. | Docs stay in sync with the registry. |
| 3 | `tests/test_metric_registry.py` | Add contract tests that reject missing or placeholder calculation text. | Targeted registry tests pass. |

## Acceptance

- Every metric definition has a clear calculation description.
- Calculation descriptions are available through `metric_catalog_payload()`.
- Documentation exposes the calculation descriptions.
- Tests fail if future metrics omit calculation metadata.
